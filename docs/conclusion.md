# Вывод

Для публикации результатов учебных и исследовательских проектов по анализу данных
(в моём случае — классификация команд на датасете MASSIVE) рекомендую стек:

- **MkDocs + Material** — сайт пишется в Markdown, сборка занимает секунды, есть
  локальный поиск с русским языком, тема не требует доработки;
- **uv** — фиксированные версии Python и пакетов, одинаковая сборка локально и в CI;
- **GitHub Actions** — сборка с `--strict`, публикация через официальный `deploy-pages`;
- **Helios** — как отечественное зеркало, выкладка по SSH/rsync с отдельным ключом
  и healthcheck.

Когда рекомендация меняется:

- много формул с нумерацией и ссылками, библиография из BibTeX, нужна PDF-версия —
  лучше **Sphinx + MyST** или **Quarto**;
- результаты в Jupyter-ноутбуках, которые надо исполнять при сборке — **Jupyter Book**
  или **Quarto**;
- нужен блог с лентой записей по датам — **Pelican**;
- GitHub недоступен или запрещён — пайплайн переносится на GitVerse / SourceCraft,
  а вместо Pages используется Helios или Object Storage;
- на хостинге нет SSH (только S3 или FTP) — меняется способ доставки и модель секретов
  (см. [T4](t4.md)).

Ограничение самого стека: команда Material for MkDocs предупреждает, что MkDocs 2.0 будет
несовместим с текущими плагинами и темами. Поэтому в `pyproject.toml` версия ограничена
`mkdocs>=1.6,<2`, а для долгоживущего проекта стоит заранее присматриваться к альтернативам
(Sphinx, Quarto).
